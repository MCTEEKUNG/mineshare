# MineShare 0.0.14

Keyboard routing and file-clipboard reliability update. Update both peers to
the same release. Windows MSI and EXE use the same upgrade engine introduced
in 0.0.13; pairing, settings and existing startup preferences are retained.

- Windows keyboard capture runs outside the foreground WebView process. This
  fixes typing, Windows-key and Alt+Tab routing while the PC controller UI is open.
- Restart isolated keyboard capture after worker failure instead of permanently
  reverting to the affected host hook. Release forwarded keys during recovery.
- Stop the GUI before keyboard workers during installer upgrades, tolerating
  workers that exit automatically when their parent closes.
- Prevent the six-file clipboard replay loop across app restarts; mark incoming
  Windows file clipboards against reflection and stop unbounded failed-batch retries.
- Copy/Paste and drag-to-send in the Files tab remain available. They are separate
  send requests: copying and then dragging the same file can intentionally send twice.

After launching/reconnecting, copy files again to send them; old file clipboard
contents are baselined rather than replayed automatically. If a file batch fails,
copy again to retry. Existing duplicate files are not automatically deleted.

Physical Windows-to-Windows acceptance passed for typing, Windows and Alt+Tab
with the controller UI visible. Forced worker termination recovered four times
without restarting the GUI. File counts stayed stable across four paired restarts.
Ubuntu uses evdev rather than the Windows keyboard worker; shared regression
tests and Ubuntu build checks apply, but no new physical Ubuntu acceptance is claimed.

Installers remain unsigned. Verify SHA-256 with the attached platform manifests.
For rollback, retain the previous installer and back up your MineShare user data;
use an explicit uninstall/reinstall for an older version (in-place downgrades
are blocked). Never delete pairing/configuration to troubleshoot an upgrade.
